# Changelog

Notable changes to Pleno. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Before 1.0, any release may change behavior.

## Unreleased

## 0.4.0 - 2026-10-27

Upgrading from 0.3: `with` is now a keyword, `exit()` throws `SystemExit`, the HTTP server listens on `127.0.0.1` by default, and the changes in bold under "Changed" alter what existing programs print or accept. Compiled `.plc` files must be compiled again (bytecode format 7).

### Added

- Middleware for the HTTP server: `router.use(fn(req, res, next) { ... })` and `router.use("/api", ...)` run before the route, in the order they were registered. `next()` runs the rest of the chain and returns its promise, so an `async fn` middleware can `await next()` and change the response afterwards; errors from the rest of the chain come out of `next()`; `next(err)` fails the request. A middleware that returns without calling `next()` or sending a response gets a 500 and a message on stderr naming it, instead of a hanging client.
- `router.onError(fn(err, req, res) { ... })` answers requests whose middleware or route failed, starting from a fresh 500 response.
- Static files: `router.static("/assets", "./public")` serves a folder with content types by extension, `index.html` for folders (and a redirect to add the trailing `/`), `HEAD`, `ETag` and `Last-Modified` with `304 Not Modified`. Paths cannot leave the folder: `..` (also encoded as `%2e%2e`), backslashes, drive letters and NUL are refused, files are normalized the way the sandbox normalizes paths (so a symbolic link out of the folder is refused), dotfiles are not served, and the sandbox's read rule applies.
- Cookies: `req.cookies`, `res.cookie(name, value, { maxAge, path, domain, httpOnly, secure, sameSite })` and `res.clearCookie(name)`. Values are percent-encoded; `httpOnly` and `sameSite: "Lax"` are on by default; an unknown option, `sameSite: "None"` without `secure`, and CR or LF in a name or value throw.
- `res.redirect(url, status?)`, `res.sent`, `req.ip`, and `server.port` (`listen(0)` picks a free port).
- `examples/web_app/app.pln`: a web app with middleware, static files, cookies and an error handler, tested over HTTP by `scripts/test_http_server.sh`.
- The release workflow publishes Scoop and WinGet updates along with Homebrew: it writes the Scoop manifest (`scripts/scoop-manifest.sh`) and pushes it to `otabekoff/scoop-bucket`, and opens the WinGet pull request with `wingetcreate update --submit` once winget has a first version. Each step needs its own token secret (`SCOOP_BUCKET_TOKEN`, `WINGET_TOKEN`) and is skipped without it. `packaging/README.md` describes the tokens and how to publish to Chocolatey and the AUR by hand, and `ide/vscode/PUBLISHING.md` how to publish the extension to the VS Code Marketplace and Open VSX.
- A Publish Extension workflow uploads a release's `.vsix` to the VS Code Marketplace (with the `VSCE_PAT` secret) and to Open VSX (by trusted publishing, without a stored token). The release workflow starts it for each new tag, and it can be run by hand for an existing release.

- `std:net` has real TCP sockets and is stable. `Net.listen(host, port)` returns a `Listener` with `accept()`, `address`, `host`, `port`, `setTimeout(ms)` and `close()`; port 0 picks a free port. `Net.connect(host, port, timeout: ms)` returns a promise for a `Socket` with `read(maxBytes)`, `readLine()`, `write(data)`, `setTimeout(ms)`, `close()`, `localAddress` and `remoteAddress`. Every operation that waits returns a promise and runs on the event loop, so a server and a client can run in one program (`examples/net_echo.pln`). Errors are clear (`connection refused: 127.0.0.1:9`, `TimeoutError: read() timed out after 500 ms`, `cannot read(): the socket is closed`), denied network access is a `SecurityError`, `close()` can be called twice, and sockets also close when nothing refers to them any more and when the program ends. Data is text (UTF-8).
- `pleno check` and the language server check more calls: methods called on a value of a known class (`let p = Point(1, 2); p.shift(1)` gives `Point.shift expects 2 arguments, got 1`, and `p.shfit()` warns `Point has no method 'shfit'; did you mean 'shift'?`), static methods (`Point.origin(1)`, and `Point has no static method 'orgin'`), lambdas bound with `let` (`let f = (x) => x; f(1, 2)`), and functions imported from another `.pln` file by a relative path, by name or through the module object. They warn about a name such a file does not export (`'./m.pln' does not export 'nmae'; did you mean 'name'?`). Type mismatches are found beyond literals when the type is certain: `let n: Int = Point(1, 2)` gives `'n' is declared Int but given a Point instance`, and the result of a function declared `: Int` is an Int.
- The language server reports compile errors, such as `cannot assign to immutable binding`, as `pleno check` does.
- The `with` statement closes resources when its block ends: `with (input = File.open("in.txt"), out = File.open("out.txt", "w")) { out.write(input.read()); }`. A resource is any value with a `close()` method, such as a `File`, a `Database`, a `Channel` or an instance of a class that defines `close`. Resources open from left to right and close in reverse order, also when the block ends with `return`, `break`, `continue` or an error. When the block throws and a `close()` throws too, the block's error propagates and the close error is added to its `suppressed` array. A value without `close()` is a `TypeError` before the block runs. `with` is now a keyword, so it can no longer name a variable or parameter; methods named `with` (`[1, 2].with(0, 5)`, or `fn with(...)` in a class) still work. Compiled `.plc` files have format version 6 and must be compiled again.
- A closed `File` handle can no longer be read: `read()` and `readLines()` throw `file is closed or not open for reading`.
- Return annotations are checked in more places. A `Void` function that returns a value throws `TypeError: f returned Int, expected Void`, and returns `null` instead of the value of its last expression. An annotation that mentions a type parameter (`fn first<T>(xs: T[]): T`) is checked against the explicit type argument (`first<Int>(...)`); an inferred one accepts any value, or any value that satisfies its constraint. A return annotated with a class of the same file and type arguments (`Box<Int>`) checks them, as a parameter does.
- Lambdas and nested functions inside a generic function or class see its type parameters: in `fn apply<T>(x: T, y) { let g = (z: T) => z; ... }`, `apply<Int>(1, "s")` throws `TypeError: parameter 'z' expected T, got String`, and `let` and return annotations in them are checked too. Before, such annotations were not checked, or, in a nested `fn` and in `let`, rejected every value.
- `@inline` functions keep their parameter and return checks where they are inlined (`TypeError: add returned String, expected Int`).
- The install scripts read `PLENO_VERSION` (install a given release), `PLENO_HOME` (install somewhere other than `~/.pleno`, as `plm` already allowed for its cache) and `PLENO_NO_MODIFY_PATH=1` (leave `PATH` alone). `install.sh` also installs the i686 Linux build, and `install.ps1` installs the x86_64 build on Windows on ARM.

### Changed

- `Server.listen(port)` listens on `127.0.0.1` (this machine only) instead of `0.0.0.0` (every network interface), as most development servers do: running a Pleno server no longer exposes it to the network or triggers a firewall prompt. `listen(port, host: "0.0.0.0")` accepts connections from other machines; `server.host` reports the address in use.
- Packages are Git repositories, and a version of a package is a Git tag `vX.Y.Z`; there is no central registry (the 1.0 decision, as in Go modules and the Swift Package Manager). A dependency is `greet = { git = "https://github.com/ada/greet", version = "^1.2" }`, or pins a `tag`, `branch` or `rev`, or is a `path`. plm picks the highest tag that satisfies every requirement on a package, and a pin in your own `pleno.toml` settles conflicts. `pleno.lock` (format `version = 1`) records every package, dependencies of dependencies included, with its exact commit and a SHA-256 checksum of its files; `plm install` keeps locked commits, checks the checksums and fails on a mismatch, a commit that disappeared or a tag that was force-pushed. Commits are fetched shallowly into a shared cache (`~/.pleno/cache`, or `PLENO_HOME`/`PLENO_CACHE_DIR`), and `--offline` installs from the lockfile and cache without network. Private repositories and any Git host work through the user's own `git` credentials; plm never stores a token. New commands: `plm add <source>[@range]` (Git URLs, `github:owner/repo`, folders) and `plm tree`; `plm update [name...]` updates some packages or all; `plm remove` also drops packages nothing needs any more; `plm publish` checks the package (valid manifest, committed tree, free tag, passing tests) and prints the `git tag`/`git push` commands, or runs them with `--push`; `plm search` points to the GitHub topic `pleno-package`. `plm add` and `plm remove` keep the comments in `pleno.toml`, and dev-dependencies are now installed. The format and the protocol are in the package manager reference.
- `Router` and `Server` in `std:http` are stable: the 1.x compatibility promise now covers them.
- A failing HTTP handler answers `500 Internal Server Error` without the error message, which can contain paths or secrets; the message is printed to stderr (or passed to `onError`). Before, it was sent to the client.
- `res.send` throws for a map or array (use `res.json`), a second `send`/`json`/`redirect` for the same request throws, and `res.status` accepts 200 to 599 only.
- `std:net`'s `listen` and `connect` take a host and a port (`Net.listen("127.0.0.1", 0)`) instead of one `"host:port"` string, and return a listener and a socket instead of a map that only described the address.
- The language reference is frozen for 1.x: `docs/specs/compatibility.md` says what "frozen" means (additions only, documented behavior kept), how errata are handled, and what stays outside the freeze. New reference sections cover numbers (overflow, division, remainder, division by zero), string literals and escapes, how each type prints, scope and shadowing, reserved words, default parameters (evaluated per call), closures and loop variables, map and set order, and the recursion and nesting limits.
- Pages for the experimental `std:gc` and `std:db` modules, and how to set Code Runner's `code-runner.executorMap` for Pleno in `docs/guide/editor.md`.
- String escapes `\0` and `\u{...}` (1 to 6 hex digits).

The changes below were made in the 1.0 review of the reference, because the compatibility promise would forbid them later.

- **Closures share the variables they use.** A function, lambda or method that read a variable kept the value the variable had when the function was created: after `let mut debug = false; fn log(m) { if (debug) print(m); } debug = true;`, `log` still saw `false`. Functions now see later assignments, as in Python and JavaScript, for top-level and local `let` variables, parameters and `for` loop variables; an assignment a closure makes to a parameter is no longer lost. Each loop iteration still has its own loop variable.
- **Floats always print as Floats:** `print(3.0)` and `print(10 / 2)` print `3.0` and `5.0` (they printed `3` and `5`), also in string concatenation, template strings and `toString()`. Very large and very small Floats use an exponent (`1e21`, `1e-7`) instead of dozens of digits. Map keys are unchanged: `m[1.0]` is still `m[1]`.
- **Strings inside containers print quoted:** `print(["1", 1])` prints `["1", 1]` (it printed `[1, 1]`), map values and tuple and enum fields likewise, with escapes for quotes and control characters. A one-element tuple prints `(1,)`, `Ok(1)`, `Err("x")`, `Some(2)` and `None` print as written instead of as maps, and a container that contains itself prints `[...]` where it repeats instead of overflowing the stack.
- **Negative slice positions count from the end in every slice form:** `a[-2..]`, `a[1..-1]`, `s[-3..]` and `a.slice(-2)` now give the last elements. Before, only `a[..-1]` did; the other forms clamped a negative start or end to 0, and `slice` treated it as a huge number.
- **Unknown string escapes are compile errors:** `"\d"` and `"C:\new\x"` used to drop the backslash silently. Use `\\` or a raw string (`r"\d"`).
- **`typeof`** gives the class name for an instance (`"Person"`, `"Error"`; it gave `"Object"`), as the reference said, and `"Function"` for every kind of function (lambdas gave `"Closure"`, built-ins `"NativeFunction"`).
- **`Math.min` and `Math.max`** take any number of arguments, or one array, and return the argument itself, so Ints stay Ints: `Math.max(1, 3, 5)` is `5`. Before, they ignored every argument after the second and always returned a Float.
- The parser's error for code nested too deeply says `code nested too deeply` instead of `Recursion limit exceeded`, and `std:log` prints values the way `print` does.
- `==` and `!=` compare arrays, tuples, maps and sets by contents, as in Python: `[1, [2]] == [1, [2]]`, `(1, "x") == (1, "x")` and `{"a": 1, "b": 2} == {"b": 2, "a": 1}` are `true` (before, only the same array, tuple or map was equal to itself). Maps ignore key order, numbers compare across Int and Float, a class's `operator ==` decides for its instances inside containers, and values that contain themselves compare without looping. `contains` and `indexOf` follow the same rules, so `[[1]].contains([1])` is `true`. Class instances without `operator ==` still compare by identity. This makes `==` agree with `assert.equal`, which already compared contents, and is made before 1.0 because the compatibility promise would forbid it later. Code that used `==` to ask whether two arrays or maps are the same object gets `true` for equal copies now; there is no identity operator yet.

### Removed

- The registry server `crates/pleno-registry` (Axum and SQLite) and its Docker files, the `PLENO_REGISTRY` and `PLENO_TOKEN` variables, publishing to a registry, and the local registry directory (`~/.pleno/registry`, `PLENO_LOCAL_REGISTRY`). A bare version string such as `greet = "^1.2"` in `pleno.toml` is now an error that shows the Git form to write. `pleno-cli` and `pleno-package` no longer depend on `reqwest`.

### Fixed

- `pleno format`, and so format-on-save in VS Code, changed what programs computed: it wrote `n *= 3 + 1` as `n = n * 3 + 1` and `out += a == b ? x : y` as `out = out + a == b ? x : y`. A compound assignment is now written as it was (`+=`, `-=`, `*=`, `/=`, `%=`), and its value keeps its grouping in the syntax tree. The formatter also wrote the documented `s[..2]` as `s[:2]`; it now writes `[..b]`.
- `assert.equal`, `assert.notEqual` and `assert.contains` now decide equality the way `==` does. Tuples (also inside arrays) and sets compared by their debug text, so `assert.equal((1, "b"), (1, "b"))` and `assert.equal(Set([1, 2]), Set([2, 1]))` failed; a class's `operator ==` was ignored; and Floats were compared with a tolerance, so `assert.equal(0.1 + 0.2, 0.3)` passed although `0.1 + 0.2 == 0.3` is false.
- `a ?? b` evaluated `b` even when `a` was not null, and twice when it was, so a call on the right ran (and could throw) every time: `status ?? args.next()` consumed an argument it did not use. The right side now runs only when the left side is null. `??` and `x is T?` also test for null without calling a class's `operator ==`.
- The Linux release programs needed glibc 2.39, the version on the build machine, so they failed with `version 'GLIBC_2.39' not found` on Ubuntu 22.04, Debian 12, RHEL 9 and older. They are now built against glibc 2.17, and CI checks this and runs `pleno` on CentOS 7.
- The instruction limit (`--max-instructions`, the playground and other sandboxes) could fail to stop a loop. It was checked only when the instruction count was a multiple of 100, and loops of fused instructions add two or three at a time, so `let mut i = 0; while (i < 2) { }` could step past every check and run forever. The limit is now checked against a threshold, and so is the collector's check of the string and big-integer tables. Found by fuzzing.
- `super(...)` crashed the VM (`internal error: entered unreachable code: expected function`) when the parent's constructor used a variable from outside its class, such as a top-level `let`. Found by fuzzing.
- A class declared in a function could not extend another class declared in the same function (`superclass must be class`), because the superclass was looked up only among globals.
- A `.pln` file or `pleno.toml` that starts with a UTF-8 byte order mark, as Notepad and PowerShell's `Out-File` can write, failed with `Unexpected character`. The mark is ignored now.
- An unknown command such as `pleno chek` was taken for a file name (`Only .pln format file extensions are supported`); it is now `unknown command 'chek'; did you mean 'check'?` (exit status 2), and `pleno tree` points to `pleno plm tree`.
- `exit(code)` skipped `finally` blocks and `with` closes, so a file written inside `with` was not closed when the program exited. `exit` now throws a `SystemExit` error (with an Int `code`), as Python's `sys.exit` does: `finally` and `with` cleanup run, a plain `catch (e)` lets it through so the program still ends, and `catch (e: SystemExit)` can stop it on purpose.
- The optimizer unrolled small constant loops without limit: loops nested inside each other multiplied (eleven `for (let i = 0; i < 3; i = i + 1)` loops became 3^11 copies of the body), and compiling ran out of memory; it also unrolled a loop whose body assigns the loop variable, so `for (let mut i = 0; i < 3; i = i + 1) { i = i + 1; }` failed with `cannot assign to immutable binding`. Unrolling now stays within a size budget and skips such loops. Found by the `fuzz_compile` fuzz target.
- A file or function that defines more than 256 functions (top-level functions, methods and lambdas together) called the wrong ones: the index of the 257th wrapped around to the first, so a call such as `run42()` ran another class's method (`missing required argument`) or a lambda returned another lambda's result, silently. Indexes now have two bytes (65,536 functions); a closure capturing more than 255 variables is a compile error instead of a wrong closure. The bytecode format version is 7; recompile `.plc` files.
- The garbage collector did not see the callbacks waiting in the event loop (timers, queued tasks, I/O handlers). A server that was not stored in a variable, as in `Server(router).listen(8080)`, lost its router and listener at the first collection, and a timer's closure could lose its captured values.
- HTTP server: `res.header` wrote CR and LF as they were, so a value taken from the request could add headers (header injection); it now throws. Query strings and route parameters are decoded (`+` and `%XX`). Header names set in different cases (`content-type`, `Content-Type`) no longer give two headers. A body over 10 MB was cut short; it now gets 413. Malformed requests get 400, oversized headers 431, a path with routes for other methods only 405 with `Allow`, and chunked request bodies are read. 204 and 304 responses have no body, responses have a `Date` header, and a port outside 0 to 65535 is an error instead of wrapping around.
- `exit(code)` from `std:process` ended the whole process from inside the VM. A program in a `Sandbox`, the playground or any embedder could stop its host. `exit` now unwinds the program like an uncaught error that `catch` cannot stop, and the host decides: `pleno run` exits with the code as before, a `Sandbox` gets a catchable `program exited with code N`, and the playground and `pleno test` treat `exit(0)` as a normal end. Found by the `fuzz_run` fuzz target.
- `pleno check` stopped at the first compile error (such as `cannot assign to immutable binding`) and reported nothing else in the file; it now reports the compile error together with the other problems it found.
- A static method called with positional arguments ignored their number and its defaults: `Point.at()` for `static at(x, y = 5)` gave `x` and `y` as `null`, extra arguments were dropped, `...rest` got only the first one, and an `async` static method returned the class. Static methods now bind arguments like any other call (`missing required argument`, `too many positional arguments`).
- `pleno check` reported `export is only allowed in modules` for every file that exports names; such a file is now compiled as a module, as importing it does.
- Compiling a file copied the whole source, and indexed its lines again, for every function, method and lambda in it, so compile time grew with the square of the file's size (70 ms for a 3,200-line file, now 21 ms). The language server, which now compiles on every change, and `pleno run` both benefit.
- `Match.group` in `sources/std/regex.pln` returns `null` for an index out of range, so its return type is `String?`, not `String`.
- A `return` that was not the last statement of an `@inline` function gave `null` instead of the returned value.
- `break` and `continue` inside a `try` or `catch` skipped the `finally` block, and `break` and `continue` out of a `try` left its error handler active, so a later error in the same function could jump back into the old `catch`. Both now run the `finally` block and remove the handler, as `return` did.
- A type parameter or an instance made without type arguments no longer rejects right values: `fn take(b: Box<Int>)` accepts `Box(1)` (it rejects `Box("s")`, since its field annotated `T` holds a `String`), `fn f<T>(b: Box<T>)` accepts any `Box`, and setting a field annotated `T` from outside the class (`b.value = 2`) is checked against the instance's type arguments, or accepts any value for an instance made without them; before, each of these threw a `TypeError`. A type parameter also comes before a global of the same name, and a parameter annotated with an extension's type parameter (`extend <T> Array<T>`) is no longer checked against an unknown type.
- A script or function with a few hundred expression statements in a row (such as 300 `print` calls) failed to compile with `too many registers in function`: each statement's value kept its register to the end. It is now freed when the next statement starts.
- Inlining an `@inline` function no longer changes what the program does. Calls in top-level code returned the wrong value (`pick(1)` returned `null` for a function with an `if` and two `return`s), and a function whose body is `return <expression>` was substituted with its arguments evaluated once per use of the parameter and its free names read where it was called. A call is now inlined only when it behaves like the call: the arguments are evaluated once, before the body, names keep their meaning, and anything else is a normal call.
- `pleno format` keeps comments inside an index (`a[/* c */ 1]`; a line comment puts the index on a line of its own), in import and export lists (`import { a, /* the b */ b }` is broken one name per line with the comment in front of `b`) and block comments in slices, parentheses and after a unary operator in place; before, they moved below the statement. A block comment after a comma in a broken list stays in front of the next element.
- `(-9223372036854775807 - 1) % -1` crashed the compiler's constant folder, and at runtime threw `integer overflow in modulo`; it is `0`.
- The formatter wrote a whole Float of 1e16 or more with all its digits, which read back as an Int (`1e17`) or did not parse (`1e21`). It keeps such literals Floats, and writes `\0` back as an escape.
- `Database.connect` in `std:db` ignored the sandbox: it now needs IO access, and read and write access to the database file under `--allow-read` and `--allow-write`.
- Two kinds of deeply nested code could overflow the stack while compiling (found by a long `fuzz_compile` run): calls on calls (`f(1)(1)(1)...`), `f<T>`, `x!`, `x++` and macro calls did not count toward the limit of 1,000 operators and calls per statement, and each `${...}` in a string started its own nesting count, so `"${"${...}"}"` 2,000 deep crashed. Both are now parse errors (`expression too long`, `code nested too deeply`), and an error in a nested interpolation says `Parse error in interpolation` once instead of once per level.
- Values stored on the built-in `Error` class (`Error.cache = box`) stayed allocated after the VM was dropped when they were part of a reference cycle: `Error` was created outside the collector's heap. It is now on the heap like any class and freed with the VM.
- The Docker image could not start its binaries: it was based on Debian 12, whose glibc (2.36) is older than the 2.39 the release binaries need. It is now based on Debian 13, includes `pleno-dap` and `git` (which `plm` runs), and `Dockerfile` builds from source again.
- The debug adapter crashed on a `setBreakpoints` or `setDataBreakpoints` request without arguments or without a `breakpoints` list; such a request now clears the breakpoints.
- `scripts/plenovm.sh uninstall` without a version removed every installed version; `plenovm use` now links all five tools, and downloads are checked against their checksums.

## 0.3.0 - 2026-10-27

### Added

- `<`, `<=`, `>` and `>=` compare strings and characters, by Unicode code point (`"abc" < "abd"`); before, they were an error.
- `Comparable` is a built-in constraint: `T: Comparable` accepts `Int`, `Float`, `String`, `Char` and classes that define `operator <` or `operator >`.
- `@deprecated` and `@deprecated("note")` on a function or method print `warning: f is deprecated: note` the first time it is called, and `pleno check` and the editor report calls to a deprecated top-level function. This is how stable APIs will be deprecated in 1.x.
- `pleno new <folder>` (and `plm new`) creates the folder and a package in it, named after the folder or `--name`; it refuses a folder that already has files. `pleno init` still sets up the current folder.
- `pleno-dap --version`, `pleno-repl --version` and `--help` for both.
- `vmStats()` in `std:reflect`: instructions executed, current and peak memory.
- `Error` is a class: `Error(message)` instances print as `Error: message` and have `toString()`; subclasses get their class name as `name`.
- Destructuring in `let`: `let (a, b) = pair;`, `let mut (x, (y, _)) = nested;` and `let [first, ...rest] = items;`, with runtime errors such as `tuple has 2 elements, pattern expects 3`. Tuple type annotations such as `(Int, String)` and `(Int, Int)[]` are checked at runtime.
- `pleno check` and the language server report wrong argument counts and unknown named arguments for functions, constructors and `this` methods declared in the file, literals that cannot match a type annotation (`let x: Int = "hi";`), and, as a warning, unknown methods called on `this`.
- `pleno run file.plc` runs bytecode written by `pleno compile`.
- Destructuring in `for` loops: `for ((k, v) in pairs)`, `for ([a, b] in rows)`, `for ((i, (x, y)) in nested)` and `for ((k, _) in m.entries())` take each item apart like a destructuring `let`, with the same errors (`tuple has 2 elements, pattern expects 3`). Over a map, a pattern matches each `(key, value)` entry. A `for` loop can also iterate an iterator such as `m.entries()` directly; before, it threw `type 'Iterator' is not iterable`.
- Return type annotations are checked at runtime, at every `return` and when a function ends without one: `fn f(): Int { return "s"; }` throws `TypeError: f returned String, expected Int`, and falling off the end of a function annotated `Int` throws `f returned Null, expected Int`. This covers functions, methods, getters, lambdas and `async` functions (whose annotation, `Int` or `Promise<Int>`, describes the resolved value). `Void`, `Any` and annotations mentioning a type parameter are not checked. `pleno check` also reports returned literals that cannot match (`f is declared to return Int but returns a String literal`).
- "Did you mean" hints: an error about a name that does not exist ends with `; did you mean 'x'?` when one existing name is close, as in `undefined variable 'lenght'; did you mean 'length'?`, `cannot read property 'pushh' of Array; did you mean 'push'?`, `Map has no method 'flor' (and no key 'flor'); did you mean 'floor'?` (for `Math.flor`), `unknown named argument 'nmae'; did you mean 'name'?` and `std module not found: jsn; did you mean 'std:json'?`. Runtime errors, `pleno check` and the language server give them; members a class keeps `private` are suggested only inside it. `pleno check` also warns about an import of a name a `std:` module does not export (`'std:json' does not export 'JSN'; did you mean 'JSON'?`).
- `Regex(pattern, flags)` applies its flags: `i` (case-insensitive), `m` (multi-line), `s` (`.` matches newlines) and `x` (verbose); `regex.flags` returns them. Before, the second argument was ignored. Unknown flag letters and invalid patterns throw when the regex is created.
- `CSV.parse(text, { header: false })` (or `header: false` as a named argument) returns every row, the first one included, for input without a header line. The default is unchanged: the first row is the header and is dropped.
- Number and Bool literals as map literal keys: `{1: "a", 2.5: "b", true: "c"}` is `{"1": "a", "2.5": "b", "true": "c"}`, since map keys are strings. Reading and writing with such an index (`m[1]`, `m[true] = x`) and `get`, `put`, `with`, `remove` and `containsKey` use the same string, so `m[1]` reads the key `"1"`.

### Changed

- `unknown named argument` errors name the argument: `unknown named argument 'nmae'`.
- The linter's `no-undef` checks unused functions and code after a `return` too, as `pleno check` does.
- A package created by `pleno new` or `plm init` starts at version 0.1.0 instead of the version of Pleno that created it.
- Programs run with an instruction or memory limit (`--max-instructions`, `--max-memory`, the playground) use the fast interpreter loop too, which checks the limits itself: about 1.6 times faster than before under a limit.
- `pleno format`, `lint`, `check`, `test`, `compile`, `watch`, `doc`, `debug-ast` and `build` reject options and arguments they do not take (`Error: 'compile' has no option '--bogus'`, exit status 2) instead of ignoring them, and print their own usage with `--help`. `pleno compile` and `pleno build` take `-o <file.plc>` and create its folder.
- `pleno build` with a target that is not a `.pln` file is an error; before, it built the package's main file instead.
- The editor's code lenses are "Run File" and "Debug File" above the first statement, instead of a "Run Function" over every function that ran the whole file.
- `plm init` no longer writes `.vscode/tasks.json` (the extension provides those tasks), its `.vscode/settings.json` only sets formatting for Pleno files and nests `pleno.lock` under `pleno.toml`, and `launch.json` drops the unsupported `stopOnEntry`.
- A variable declared without `mut` (or with `const`) can no longer be reassigned from inside a function or closure; before, `let x = 1; fn f() { x = 2; } f();` changed `x`. Assigning to a name declared with `fn`, `class`, `enum` or `interface` says so (`cannot assign to function 'g'`) instead of `unknown local or global`.
- Compile errors in unused functions and classes and in code after a `return` are reported by `pleno run` and `pleno check`; before, the optimizer dropped that code first and its errors went unnoticed until it was used.
- Every caught error is an `Error` instance with `name` and `message`: runtime errors, failed type annotations (`TypeError`), denied operations (`SecurityError`) and sandbox limits (`SandboxError`) included, so `catch (e: Error)` catches them and `e.message` always works.
- Printing an error or putting it in a string gives `name: message`, such as `TypeError: parameter 'x' expected Int, got String`, instead of a map.
- Caught errors no longer carry `peakMemory` and `instructions`; `vmStats()` from `std:reflect` returns them.
- Ints and Floats compare by value: `5.0 == 5` is true, so `assert.equal(10 / 2, 5)` passes. Sets, `contains` and `indexOf` follow the same rule (`Set([5, 5.0])` has one element).
- `.plc` files start with a `PLNC` magic number and a bytecode format version, checked on load; files from another Pleno version, older headerless files and truncated files are rejected with an error asking to recompile.
- Faster execution: recursive `fib(30)` runs in 0.12 s instead of 2.1 s, a 10-million-step loop in 0.26 s instead of 0.9 s, and `map`/`filter`/`reduce` over a million elements about 3 times faster. Calls pass their arguments in registers, global lookups are cached, common instruction pairs run as one, and strings and big integers no longer pile up until the next object collection.
- An `Int` is accepted where a `Float` is annotated and is converted to a `Float` there (parameters, `let`, assignments, fields, return values, `Float?`, unions such as `Float | String`); before, `fn f(x: Float) {} f(3);` and `let y: Float = 3;` threw a `TypeError`. In a union that allows `Int` (`Int | Float`, `Number`) an `Int` stays an `Int`, and `Float[]` accepts `Int` elements without converting them. `pleno check` now reports a `Float` literal given for an `Int` annotation.
- Reassigning a `&mut` parameter (`value = ...`, `value++`) is a compile error, `cannot assign to '&mut' parameter 'value'`: the new value never reached the caller's variable. Changing a value in place (`items.push(x)`) is unchanged.
- Faster still: Pleno now beats CPython 3.14 on every benchmark in `bench/cases` and on `bench/src/array` (`fib(30)` 0.09 s against 0.10 s, the array benchmark 0.16 s against 0.17 s). Method calls such as `items.push(x)` no longer allocate a bound method, `s = s + x` appends in place when nothing else holds the old string (building a string is linear instead of quadratic), values take 16 bytes instead of 40, simple instructions run in a smaller interpreter loop, and calls and `map`/`filter`/`reduce` callbacks set up their frames with less work.
- The bytecode format version is 4 (new `ToFloat`, `CallRegs`, `GetMethod` and `CallMethod` instructions); recompile `.plc` files.
- `Crypto.jwtVerify` checks the `exp` and `nbf` claims against the current time and throws `JWT expired` or `JWT not valid yet`, the way it throws `Invalid JWT signature`; it also rejects tokens whose header `alg` is not `HS256`. Signatures are compared in constant time (`hmac`'s `verify_slice`). `jwtSign` and `jwtVerify` are now stable.
- `JSON.stringify` and `stringifyPretty` write a class instance as an object of its public fields (private, protected and internal fields are left out) and a set as an array of its elements, a `Char` as a one-character string; before, all three became `null`. A value nested more than 512 levels deep (such as a map that contains itself) throws instead of overflowing the stack.
- The bytecode format version is 5 (new `ToFloat`, `CallRegs`, `GetMethod` and `CallMethod` instructions, and a `GetIterator` mode for destructuring `for` loops); recompile `.plc` files.
- `pleno format` (and format on save in the editor) keeps lines within 100 characters, the linter's limit. A statement that does not fit is broken at its outermost construct: call arguments, array, map, set and tuple literals, parameter lists and import and export lists go one element per line with a trailing comma, chains of two or more method calls one call per line, and binary operator chains before each operator. A statement that fits is printed on one line, also when it was written over several; before, every statement was joined into one line however long. Strings and comments are never split.
- Dependencies: thiserror 2, rand 0.10, base64 0.23, toml 1.1, rusqlite 0.40, sha2 0.11, hmac 0.13, aes 0.9, cbc 0.2, num-derive 0.5, notify 8, dirs 7, mockall 0.15, axum 0.8 and tower-http 0.7 (the package registry's routes use axum 0.8's `{name}` syntax; Pleno's own HTTP server is unaffected and keeps `:id`). bincode stays at 1.3, so `.plc` files are unchanged.

### Fixed

- A `@pure` function could not build an array, map or set: `@pure fn f(x) { return [x, 1]; }` threw `pure function cannot have side effects`. Literals (with spreads) are allowed now; assigning to a field or an index is still rejected. Map literals use a new `MapLiteralSet` instruction.
- A method value printed as `<method of Class(GcRc { ptr: 0x7d75d7e83c90 })>`, a memory address that changed from run to run. It now prints `<method of Shape>` (and `<static method of Shape>`); a bound generic function prints its function instead of its debug form.
- Parameter annotations on lambdas and anonymous functions were not checked: `fn(x: Int) => x` accepted a string. They are now checked when the lambda is called, like a named function's (`TypeError: parameter 'x' expected Int, got String`), with `Int` widening to `Float` and optional and union annotations. Arrow lambdas take annotations too: `(x: Int) => x * 2`. A failed parameter check now points at the parameter instead of the first line of the file. Unannotated lambdas cost the same as before.
- An error raised deep in the call stack no longer copies the whole stack into its backtrace. A `catch` that throws again at each of 16,000 nested levels took 5 seconds, and the time grew with the square of the depth; it now takes about 0.1 seconds. A backtrace deeper than 60 calls keeps the innermost 50 and outermost 10 frames, with a `... N more frames` line between them.
- A very long chain of operators or calls in one statement (`1 + 1 + ...` with tens of thousands of terms) overflowed the stack while compiling. A statement can now chain up to 1,000 operators and calls; a longer one is a parse error (`expression too long`). The browser playground gets an 8 MB WebAssembly stack instead of 1 MB. Found by the `fuzz_compile` fuzz target.
- Generic constraints were checked only with explicit type arguments: `greet(Rock())` with `fn greet<T: Named>(x: T)` was accepted and failed later. A parameter annotated `T` is now checked against `T`'s constraints, and the error names them (`expected T: Named, got Rock`). `T: Comparable` rejected `Int`.
- Runaway recursion crashed the process: plain recursion grew memory until an allocation failed, and recursion through callbacks (`map`, operators, `test` inside `afterEach`) overflowed the stack. Both now raise a catchable `RecursionError`: calls can nest 100,000 deep, and calls from built-in functions back into Pleno 200 deep (64 in the browser playground). Found by the `fuzz_run` fuzz target.
- String positions and lengths count Unicode characters everywhere, as the reference says: `length`, `s[a..b]`, `indexOf`, `substring`, `charAt`, a regex match's `index` and `assert.lengthOf` counted UTF-8 bytes while `s[i]` counted characters, so `"héllo".length` was 6. `"héllo".substring(0, 2)` and `charAt(1)` stopped the VM with a panic; they now give `hé` and `é`. `split("")` returns the characters (`["a", "b", "c"]` instead of `["", "a", "b", "c", ""]`). `substring` clamps negative positions to 0 and swaps its arguments when `start > end`, like JavaScript (before, both gave `""`), and `repeat` with a negative count throws an error instead of stopping the VM.
- Sandbox path rules (`--allow-read`, `--allow-write`, `allowedReadPaths`, `allowedWritePaths`) compared text prefixes, so `data/../secret.txt` passed a rule for `data/` and `data2/` passed a rule for `data`. They now compare normalized absolute paths, folder by folder. `Path.exists`, `isFile`, `isDir`, `resolve` and `dotenv.config` count as reading, and `process.cwd()` needs I/O.
- A sandbox option with a value that does not parse (`--allow-io maybe`, `--max-memory 10MB`) meant "allowed" or "no limit"; it is now an error.
- A sandbox limit (`--max-instructions`, `--max-memory`, `Sandbox` options) could be caught by `try`/`catch`, so a program could catch it and run on past its limit. Reaching a limit now ends the sandboxed program; the program that started a `Sandbox` still catches it as a `SandboxError` (before, that error arrived named `Error`).
- `a != b` ignored a class's `operator ==`: with `==` overloaded, `V(1) != V(1)` was `true`. It is now `!(a == b)` unless the class defines its own `operator !=`.
- An error thrown inside a callback (`map`, `filter`, ...) and caught outside read `uncaught exception: uncaught exception: ...`; it now has its own message.
- Code in a module could call the top-level functions and classes of the program that imported it (`helper()` in a module found the main program's `helper`). A module now sees its own names, its imports and the built-in globals only, and still gets the built-in `print` or `typeof` when the main program defines its own.
- A callback given to `map`, `filter` and the other natives that call back returned its first argument instead of `null` when that argument was a map with a `variant` key: `[Ok(1)].map(|r| => null)` was `[Ok(1)]`.
- An array or map literal made only of constants (`[]`, `[0, 0]`, `{"n": 0}`) was created once and shared: a function returning `let a = []; a.push(1); return a;` gave the same array on every call, so it grew. Each evaluation now creates a new one.
- Changing an array inside its `reduce` callback, or a set inside its `forEach` or `filter` callback, crashed the VM (`RefCell already borrowed`). These now iterate over the elements as they were when called, like `map` and `forEach` on arrays.
- The linter (and so the editor) no longer reports lambdas (`=>`) and generic types (`Promise<Int>`) as operators missing spaces, type aliases and other names used only in type annotations as unused, or standard library globals such as `Ok`, `Some`, `Set` and `Error` as undefined. Functions can be used before their declaration, the line limit is 100 and skips comments, and every warning points at the whole name or operator.
- Intersection types (`type Person = Nameable & Ageable;`) accept a value that matches every part; before, a class implementing both interfaces was rejected with `expected Person, got Employee`.
- Type aliases inside a larger annotation (`Money?`, `Money | String`, `Money[]`) and as class field types are expanded before checking.
- An import makes visible only the names it binds. Other exports and the private names of an imported module no longer leak into the importing file (`import { PI } from "./m.pln"; square(2);` is now `undefined variable 'square'`), and names a module imports stay in that module.
- A denied field access names the rule instead of `field access denied` or `static field access denied`: `cannot read protected field 'name' of B outside its class`, `cannot assign to private static field 'count' of Counter outside its class`, `cannot read internal field 'f' of Ex2 outside its module`.
- Field visibility is checked against the class that declares the field, also on instances of subclasses: a subclass's methods can no longer use a `private` field of its parent.
- `abstract fn` in a class that is not `abstract` is a compile error.
- A class with an `internal` field can be created and used from another module: `internal` means visible within the declaring module, and the class's constructor and methods run in it.
- Inherited `protected` fields can no longer be read or assigned from outside the class hierarchy.
- Creating a class that does not implement an abstract method of its parent throws `cannot create B: it does not implement abstract method area`, also when constructed with named arguments; constructing an abstract class with named arguments is rejected too.
- `static const` fields cannot be reassigned (`cannot assign to constant MathUtils.PI`), and instance `const` fields can be assigned only by a constructor.
- `let mut y = x;` made `y` share `x`'s storage, so assigning either changed both (in every scope, for numbers and strings alike).
- `CSV.parse` errors no longer repeat their prefix (`CSV error: CSV error: ...`).
- `XML.parse` throws on input without a complete root element: `XML parse error: no root element` for an empty string (or only comments or text) and `XML parse error: element <a> is not closed` for `<a>`. Before, it returned `null`.
- The HTTP server answers `HEAD` on a `get` route like `GET` (same status and headers, `Content-Length` included) without a body; before, it answered 404. Tests now serve real requests to a running server.
- The formatter changed programs and moved comments: `else if` became `else { if ... }`, annotations on methods (`@override`) and the `out`/`in` of generic parameters were dropped, and comments inside a multi-line call, list, method chain, `match` or `enum` moved below the statement (a doc comment on an enum variant ended up on the next declaration). Comments now stay next to the element they belong to.
- Dropping a VM left every value in a reference cycle allocated: an object whose field points back at it, a closure that reaches itself through a map, an instance holding a closure that captures it, a class and its methods. Hosts that run many programs in one process (the language server, the REPL, the browser playground, test runners) grew with every run; 58 of the programs in `tests/`, `examples/` and `dev-tests/` kept memory after their VM was dropped, up to 4 KB per run. Dropping a VM now frees everything it allocated, and once a thread's last VM is gone, its table of strings, big integers and ranges is emptied too. Values the embedder still holds, such as the result of `execute`, stay intact with everything they reach and are freed when dropped.
- A garbage collection emptied the array, map or object behind an iterator that was no longer used: after `let it = list.iterator()` in a function that returned, `collect()` left `list.length` at 0 instead of 3, and a `for` over `map.entries()` emptied `map`. Collections now only drop the iterator's reference.

### Documentation

- The language reference (`docs/specs/`) describes only what Pleno implements and is the basis of the 1.0 specification. Claims that were not true were corrected, among them: `@pure` is a partial runtime check (now marked experimental), `@override`, `@sealed` and `@deprecated` have no effect, generic constraints are checked only with explicit type arguments, strings cannot be iterated, and `pleno check src/`, `lint --fix`, `format --check`, `test --coverage`, `doc --serve`, `run --timeout` and the `--verbose`/`--quiet`/`--color` options do not exist. New: truthiness rules, global functions, a collection method reference and a known-bug note on string positions.
- New page: the [1.x compatibility promise](https://pleno.mohirlab.uz/specs/compatibility), saying what 1.x guarantees and what it does not (bytecode format, error wording, performance, experimental APIs).
- The standard library list marks every module and API as stable or experimental. `std:net`, `std:security`, `std:gc` and `std:db` are experimental, as are the `std:http` server, `Crypto.jwtSign`/`jwtVerify` and `vmStats`.
- Designs that are not implemented moved from `notes/specs.md` and `notes/v2-specs.md` to `notes/v2-draft.md`. The performance, bytecode VM, distribution and release pages are labelled as implementation or planning notes.

## 0.2.0 - 2026-10-24

### Changed

- Reading an undefined name is an error (`undefined variable 'foo'`) instead of `null`, and `pleno check` reports undefined names.
- An unhandled promise rejection ends the program with an error instead of a warning.
- A failing `std:test` test fails `pleno test`, `plm test` and `pleno run`.
- Relative imports resolve from the importing file's folder, not the working directory.
- `plm publish` and `plm search` need `PLENO_REGISTRY`; there is no default registry.
- Uncaught exceptions print their message instead of the error map.
- Division and modulo by zero are errors for every Int and Float combination.
- A program whose top-level `await` can never finish ends with an error instead of exiting silently.
- Calling a method a map does not have names the method (`Map has no method 'contains'`) instead of `Null is not callable`.

### Added

- Backtick strings, generic type aliases, `extend <T> Array<T>`, enum methods after `;`, and `return` in match arms.
- `Result` and `Option` type annotations.
- Every standard library module can be imported as a namespace (`import { Path } from "std:path"`), plus `std:core` and `std:promise`.
- `DateTime` and `Duration`, `JSON.stringifyPretty`, `Regex.split`, `Benchmark.measure`, `Log.setLevel`, prefixed loggers, and collection helpers.
- `pleno check --json`; colored output on terminals (`NO_COLOR` and `FORCE_COLOR` are respected).
- VS Code extension 0.2.0, which can install the toolchain.
- A new documentation site with a tutorial and a playground that runs Pleno in the browser (WebAssembly). Every example in the docs is checked in CI.

### Fixed

- Infinity and NaN, 64-bit integers, enum type annotations, typed `catch` branches, contravariant interfaces, the pipeline operator with arguments, and iterating a channel.
- The formatter keeps comments, escapes and syntax it used to drop or break.
- Crashes on deeply nested code in the language server, and on malformed generic annotations in the compiler.
- A VM crash (index out of bounds) when a plain function returned a call to an async function that was waiting, and async functions called from `map`, `filter` and other built-ins returning `null` instead of their promise.
- `test()` with an `async fn` body reports its result when the body finishes, and a failure after an `await` fails the run.
- `Promise.all` put results in the wrong places, dropped some, and never finished when it mixed promises with plain values.
- Built-in functions called through a value (`xs |> map(f)`) could call the wrong function in the WebAssembly build.
- `std:test` output now goes wherever the program's output goes (the playground, the debugger).
- `Path.resolve` no longer returns `\\?\` paths or mixed separators on Windows; `Math.randomInt(n, n)` returns `n`; `unwrap()` on an `Err` shows the error.
