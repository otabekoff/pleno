# Pleno 1.0: what is left

Status checked against the code on 2026-10-27. Only open work is listed: an item that is
completely done is removed and logged in [`done.md`](done.md). Everything about releases,
signing, package managers and the extension stores is in [`distribution.md`](distribution.md).

**What 1.0 means:** people can install Pleno with one command on Windows, macOS and Linux, write
programs and libraries in it, and rely on it. Behavior is documented, does not change within 1.x,
and the tools fail loudly and clearly instead of crashing or guessing.

## Must have (blocks 1.0)

- [ ] **Freeze the 1.0 language specification.** Status: `docs/specs/` describes only what is
      implemented (checked claim by claim on 2026-10-25), every example in it runs in CI, and every
      difference found between it and the implementation is fixed. The last of those were `@pure` with
      literals (#142) and `==` comparing arrays, tuples, maps and sets by contents (#159).
      `docs/specs/compatibility.md` is the written 1.x promise. Missing: the maintainer's last review
      of `docs/specs` and of these decisions, then a note in `compatibility.md` that the reference is
      frozen for 1.x.
- [ ] **Fuzzing time.** Status: four targets (lexer, parser, compiler, and `fuzz_run`, which runs
      programs with both interpreter loops and compares them) run on pull requests and weekly, under
      AddressSanitizer with leak detection (#155). Every crash the long runs found is fixed, the last
      being deep call chains and nested interpolations in the compiler (#153). Missing: long runs
      (`gh workflow run fuzz.yml -f seconds=19800`, about 5.5 hours, the most a GitHub job allows)
      that find nothing for a full day in total. Run [40460292917](https://github.com/otabekoff/pleno/actions/runs/40460292917)
      started on 2026-10-27.
- [ ] **A release people can install.** Status and every open step:
      [`distribution.md`](distribution.md).

## Should have (1.0 or soon after)

- [ ] **More static checking.** Status: `pleno check` and the language server report syntax and
      compile errors, undefined names, wrong argument counts and unknown named arguments (for
      functions, constructors, methods on `this` and on values of a known class, static methods,
      lambdas bound with `let`, and functions imported from `.pln` files), unknown methods (a
      warning), and values whose type is certain (literals, instances of a class declared in the
      file, results of functions with a checked primitive return type, and names bound once to
      them) that cannot match a primitive annotation. Missing:
  - the types of parameters, `let mut` variables and expressions such as `a + b`;
  - annotations that name classes, aliases or generic types;
  - parameter defaults and fields;
  - classes imported from other files (their constructors and methods), and unknown members read
    through a module object (`m.nme()`), which would need the names of the map methods;
  - files imported by package name (`import x from "pkg"`) or from `std:` sources.
- [ ] **Runtime type checks not done yet.** Status: parameters, `let`, assignments, fields and
      returns are checked, including on lambdas. Missing: return checks for `Void`; annotations that
      mention a type parameter (in returns, and in a lambda inside a generic function); the type
      arguments of user generic classes; `@inline` functions.
- [ ] **Speed.** Status: faster than CPython 3.14 on every benchmark in `bench/` (fib 0.090 s
      against 0.099 s, loops 0.029 against 0.078, strings 0.018 against 0.029; the full table is in
      `done.md` under 2026-10-25), also with an instruction limit set. Missing:
  - the margin on calls is small: a call still writes a 120-byte frame and goes through the
    register vector's bounds checks;
  - the small interpreter loop is off while a debugger is attached;
  - a closure created in a loop copies its function's code each time (`Closure` pushes a new
    `Function`).
- [ ] **HTTP server connections.** Status: `Router` and `Server` are stable, with middleware,
      static files and cookies. Each request is read and written with blocking I/O on the program's
      thread, with a 5 second timeout, so a client that sends slowly delays every other client.
      Missing: reading requests through the event loop (non-blocking, one parser state per
      connection), and keep-alive. Neither changes the API.
- [ ] **Web framework features.** Status: `std:http` has a router with `:param` routes, query
      strings, headers, bodies, `HEAD`, `res.status/header/send/json` and async handlers, with tests
      that serve real requests. `Router` and `Server` stay experimental because the features below
      may change `req` and `res`. Missing: middleware (`app.use`), static files and cookies.
- [ ] **Error suggestions not covered yet.** Status: `; did you mean 'x'?` is given for undefined
      variables, unknown properties and methods, enum variants, named arguments, `std:` modules and
      their exports, and the exports of `.pln` files imported by relative path. Missing: at runtime,
      the locals of the functions enclosing a closure; type names in annotations.
- [ ] **Formatter: comments that move.** Status: lines are kept within 100 characters, and
      comments in broken lists, chains, `match` arms and `enum` bodies stay in place. Missing: a
      comment in a place that cannot break, such as inside an index or an import list, still moves
      below the statement.
- [ ] **Split the VM's `lib.rs`.** Status: `crates/pleno-vm/src/lib.rs` is about 8,000 lines
      (dispatch, calls, classes, exceptions, generics checks, iteration). Missing: modules small enough
      to review, and replacing `unsafe` blocks that do not pay for themselves with safe code.
- [ ] **Documentation for experimental modules.** Status: `std:gc` (`collect`, `heapSize`,
      `isEnabled`, `report`, `stats`) and `std:db` (`Database.connect("sqlite:path")`) are listed in
      `docs/stdlib/index.md` but have no page. Missing: a page for each, needed before either can
      become stable.
- [ ] **Code Runner support.** Status: the VS Code extension has its own Run command. Missing:
      Code Runner's executor map is a user setting the extension cannot safely change, so document the
      setting instead.
