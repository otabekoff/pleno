# Pleno 1.0: what is left

Status checked against the code on 2026-10-24.

**What 1.0 means:** people can install Pleno with one command on Windows, macOS and Linux, write programs and libraries in it, and rely on it. Behavior is documented, does not change within 1.x, and the tools fail loudly and clearly instead of crashing or guessing.

## Must have (blocks 1.0)

- [ ] **Freeze the 1.0 language specification.** Status: `notes/specs.md` mixes implemented, partial and future features, and some sections marked ✅ were wrong (enum type annotations and `x |> f(a)` did not work until this month). Every code block in `docs/` now runs, but there is no single document saying what 1.x guarantees. Missing: a 1.0 spec with only implemented features, everything else moved to a v2 draft, and a written compatibility promise.
- [ ] **Speed.** Status: on a recursive Fibonacci plus a 3-million-step loop, Pleno takes 0.98 s and CPython 0.35 s (release build, 2026-10-24). Missing: profiling of dispatch, NaN-box decoding and call frames, and a target of at least CPython speed on `bench/cases`.
- [ ] **One error shape.** Status: runtime errors are thrown as maps with `message`, but compiler-generated type errors are thrown as strings, so `catch (e) { e.message }` works for one and not the other. Runtime error maps also carry VM statistics (`peakMemory`, `instructions`), which show up when a caught error is printed.
- [ ] **Destructuring.** Status: tuples, `.0` access and named tuples work. Missing: `let (a, b) = pair;`, `let [x, y] = items;` and tuple type annotations, which the spec and docs describe (marked "planned" in the docs).
- [ ] **Bytecode format version.** Status: `pleno compile` writes `.plc` files with no header, so a newer `pleno` would misread older files. Missing: a magic number and format version checked on load, or no `.plc` files in 1.0.
- [ ] **Fuzzing time.** Status: three targets run for 2 minutes on pull requests and weekly; `fuzz_compile` found a compiler panic within 2 minutes on 2026-10-24 (fixed). Missing: long runs (hours) until a full day finds nothing.
- [ ] **A release people can install.** Status: v0.1.0 binaries predate this month's fixes and have no `pleno-dap`; Windows binaries are unsigned (SignPath application ready in `notes/SIGNPATH_APPLICATION.md`); install scripts and a VS Code installer exist. Missing: a new release, signed Windows binaries, and packages for winget or Scoop, Homebrew, and a Linux package manager.
- [ ] **Class and module rules that are not enforced (found 2026-10-24).** Exported functions and classes also leak into the importer's global scope (`import { PI } from "./m.pln"; print(square);` works); a class with an `internal` field cannot be constructed from another module; inherited `protected` fields can be read from outside; a subclass that does not implement an abstract method can be instantiated; `static const` fields can be reassigned; intersection types (`A & B`) reject a class implementing both; assigning to a `&mut String` parameter does not change the caller's variable.
- [ ] **Int and Float equality.** `5.0 == 5` is false while `5.0` prints as `5`, so `assert.equal(10 / 2, 5)` fails with `got 5 and 5`. Decide: numeric equality across Int and Float (like Python and JavaScript), or print floats as `5.0`.
- [ ] **Std library guarantees.** Status: every documented call runs, and every module offers a namespace and named imports. Missing: a list of which APIs are stable in 1.0; `std:net` (see below) must be finished or removed from 1.0.

## Should have (1.0 or soon after)

- [ ] **Std library gaps found while checking the docs (2026-10-24).** `Regex(pattern, flags)` ignores its second argument (inline `(?i)` works); `CSV.parse` always treats the first row as a header and drops it; map literals accept only string keys (`{1: "a"}` is a parse error); `Crypto.jwtVerify` does not check `exp` and compares signatures in non-constant time; `JSON.stringify` writes class instances as `null`.

- [ ] **More static checking.** Status: `pleno check` reports syntax errors, compile errors and undefined names, and the language server syntax errors. Both also report, conservatively (done): wrong argument counts and unknown named arguments for top-level functions, constructors and `this` methods declared in the same file; unknown methods on `this` (a warning, for classes whose members are all known); and literals that cannot match a primitive annotation in `let` and in calls to those functions. Missing: compile errors and undefined names in the language server, calls on other receivers (`obj.method()` with a known class, static methods), calls to functions from imported modules, lambdas bound with `let`, mismatches beyond literals (inferring variable and return types), annotations that name classes, aliases or generic types, and parameter defaults and fields.
- [ ] **Error messages with suggestions.** Status: errors give the right line, operand types and actual types. Missing: "did you mean" suggestions for misspelled names and methods.
- [ ] **TCP sockets (`std:net`).** Status: `listen` binds and `connect` connects, but both close the socket at once and return a plain map. Missing: a socket resource with `accept`, `read`, `write` and `close`.
- [ ] **Web framework features.** Status: `std:http` has a router with `:param` routes, query strings, headers, bodies, `res.status/header/send/json` and async handlers. Missing: middleware (`app.use`), static files and cookies.
- [ ] **`with` statement** for resources that close themselves (`with (f = File.open(...)) { ... }`). Status: not started; the docs mark it as planned.
- [ ] **Package registry decision.** Status: `crates/pleno-registry` is a registry server (Axum + SQLite) and `plm` can publish to a registry URL from `PLENO_REGISTRY`, but none is deployed. Missing: either a hosted registry or Git-based dependencies as the 1.0 answer, and a documented protocol.
- [ ] **Language server tests and features.** Status: definition, references, rename, hover, completion, signature help, inlay hints, semantic tokens, folding, formatting, code lens, call hierarchy and code actions work. Missing: integration tests for the server and workspace symbol search.
- [ ] **Formatter details.** Status: every test and example still passes after formatting and a second pass changes nothing. Missing: comments inside a multi-line expression move below the statement, and long lines are not wrapped (`max_line_length` is unused).
- [ ] **Split the VM's `lib.rs`.** Status: `crates/pleno-vm/src/lib.rs` is about 6,200 lines (dispatch, calls, classes, exceptions, generics checks, iteration). Missing: modules small enough to review.
- [ ] **Code Runner support.** Status: the VS Code extension has its own Run command. Missing: Code Runner's executor map is a user setting the extension cannot safely change; document the setting instead.
