# Pleno 1.0: what is left

Status checked against the code on 2026-10-24.

**What 1.0 means:** people can install Pleno with one command on Windows, macOS and Linux, write programs and libraries in it, and rely on it. Behavior is documented, does not change within 1.x, and the tools fail loudly and clearly instead of crashing or guessing.

## Must have (blocks 1.0)

- [ ] **Freeze the 1.0 language specification.** Done (2026-10-25): `docs/specs/` was checked claim by claim against the implementation and now describes only what exists (it is the 1.0 reference); unimplemented designs moved to `notes/v2-draft.md`, and `notes/specs.md` and `notes/v2-specs.md` were folded into it; `docs/specs/compatibility.md` is the written 1.x promise; implementation and planning pages (performance features, bytecode VM, distribution, release) are labelled as not guaranteed; `@pure` is marked experimental. Missing: fix the differences between the reference and the implementation listed under "Bugs that block the freeze" in `notes/v2-draft.md` (`!=` ignores `operator ==`; `@pure` rejects array and map literals; an instruction limit hit inside `try` exits silently with status 0; `Sandbox.run` errors lose their `name`), a deprecation warning (`@deprecated` does nothing today, but the promise says deprecations warn), and the maintainer's review before the reference is declared frozen.
- [ ] **Speed.** Status: profiled and optimized on 2026-10-25 in two stages. Stage 1: arguments passed in registers, no copy of the function per call, cached global lookups, fused instruction pairs, cheaper frames. Stage 2: method calls without a bound method (`GetMethod`/`CallMethod`), in-place `s = s + x` for strings nothing else holds, 16-byte values, a small interpreter loop for simple instructions (`run_fast` in `pleno-vm`), lighter frames and native callbacks. Pleno is now faster than CPython on every benchmark below. Seconds, release build, best of 9 interleaved runs on one (busy) Windows machine, process start included (about 20 ms for Pleno, 35 ms for CPython):

  | Benchmark | Pleno stage 1 | Pleno now | CPython 3.14 |
  | --- | --- | --- | --- |
  | `bench/cases/fib` (fib(30)) | 0.151 | 0.090 | 0.099 |
  | `bench/cases/loop` (1M steps) | 0.040 | 0.029 | 0.078 |
  | `bench/cases/string` | 0.042 | 0.018 | 0.029 |
  | `bench/cases/collection` | 0.020 | 0.016 | 0.030 |
  | `bench/src/fib` | 0.118 | 0.074 | 0.080 |
  | `bench/src/loop` (10M steps) | 0.249 | 0.186 | 0.391 |
  | `bench/src/array` (1M elements) | 0.481 | 0.156 | 0.170 |
  | fib(27) plus a 3-million-step loop | 0.102 | 0.060 | 0.163 |

  Missing: the margin on calls is small (fib is about 10% ahead): a call still writes a 120-byte frame and goes through the register vector's bounds checks. The small loop is off while a debugger is attached or a sandbox sets limits (the playground runs with an instruction limit), so those run at stage-1 speed. Closures created in a loop copy their function's code each time (`Closure`/`FunctionRef` push a new `Function`).
- [x] **One error shape.** Done: every caught runtime, type annotation and native error is an instance of the built-in `Error` class with `name` (`Error`, `TypeError`, `SecurityError`, `SandboxError`, ...) and `message`, prints as `name: message`, and is caught by `catch (e: Error)`. VM statistics moved to `vmStats()` in `std:reflect`.
- [x] **Destructuring.** Status: done. `let (a, b) = pair;`, `let mut`, nesting, `_`, `let [x, ...rest] = items;` and tuple type annotations (`(Int, String)`, checked at runtime) work, with clear errors for a value of the wrong shape. `for` loops take the same patterns (`for ((k, v) in pairs)`, `for ([a, b] in rows)`, nested, with `_`); over a map a pattern matches each `(key, value)` entry, and an iterator such as `m.entries()` can be looped over.
- [x] **Bytecode format version.** Status: done. `.plc` files start with the magic `PLNC` and `BYTECODE_FORMAT_VERSION` (in `pleno-bytecode`); `pleno run file.plc` checks both and rejects foreign, other-version and truncated files with a clear error.
- [ ] **Fuzzing time.** Status: three targets run for 2 minutes on pull requests and weekly; `fuzz_compile` found a compiler panic within 2 minutes on 2026-10-24 (fixed). Missing: long runs (hours) until a full day finds nothing.
- [ ] **A release people can install.** Status: v0.1.0 binaries predate this month's fixes and have no `pleno-dap`; Windows binaries are unsigned (SignPath application ready in `notes/SIGNPATH_APPLICATION.md`); install scripts and a VS Code installer exist. Missing: a new release, signed Windows binaries, and packages for winget or Scoop, Homebrew, and a Linux package manager.
- [x] **Class and module rules that are not enforced (found 2026-10-24).** Done (2026-10-25): an import binds only the names it lists (or its namespace name), and a module's other top-level names stay in the module; `internal` means visible within the declaring module, so its constructor and methods work when the class is used from another file; inherited `protected` and `private` fields are checked against the class that declares them; creating a class that leaves an abstract method undefined throws `cannot create B: it does not implement abstract method area`, and `abstract fn` in a non-abstract class is a compile error; `static const` fields cannot be reassigned and instance `const` fields only in constructors. Intersection types and `&mut` parameters are covered under Runtime type annotations. A module can no longer read the top-level names of the program that imports it (2026-10-26).
- [x] **Runtime type annotations.** Done: an `Int` is accepted where a `Float` is annotated and becomes a `Float` (parameters, `let`, assignments, fields, returns, `Float?`, `Float | String`; an `Int` stays an `Int` in `Int | Float`; `Float[]` elements are accepted, not converted). Return annotations are checked at every `return` and at the end of the function (`TypeError: f returned String, expected Int`), for functions, methods, getters, lambdas and `async` functions (the resolved value). Intersection types (`A & B`) accept a value matching every part. Reassigning a `&mut` parameter is a compile error (it never reached the caller). Not done: return checks for `Void`, for annotations that mention a type parameter, for the type arguments of user generic classes and for `@inline` functions; lambda parameter annotations are not checked at all.
- [x] **Int and Float equality.** Done: numbers compare by value across Int and Float, exactly as in Python (`5.0 == 5`, `9007199254740993 != 9007199254740992.0`); `!=`, `assert.equal`, set membership, `contains` and `indexOf` agree.
- [x] **Std library guarantees.** Done (2026-10-25): `docs/stdlib/index.md` lists every module with its stability, and each module page starts with a stability line. Stable: every module except `std:net`, `std:security`, `std:gc` and `std:db` (experimental). Experimental inside stable modules: `Router`/`Server` in `std:http` (no tests serve requests), `jwtSign`/`jwtVerify` in `std:crypto`, `vmStats` in `std:reflect`. `std:net` is experimental, outside the 1.0 promise, because `listen`/`connect` close the socket at once. Regex flags, the CSV header and `JSON.stringify` of class instances are documented as they behave (the last as unspecified). Remaining: tests that serve HTTP requests before `Router`/`Server` can become stable, and documentation pages for `std:gc` and `std:db` if they are to be stable.

## Should have (1.0 or soon after)

- [ ] **Std library gaps found while checking the docs (2026-10-24).** `Regex(pattern, flags)` ignores its second argument (inline `(?i)` works); `CSV.parse` always treats the first row as a header and drops it; map literals accept only string keys (`{1: "a"}` is a parse error); `Crypto.jwtVerify` does not check `exp` and compares signatures in non-constant time; `JSON.stringify` writes class instances and sets as `null`; `XML.parse("")` and `XML.parse("<a>")` return `null` instead of throwing; `CSV.parse` errors repeat their prefix (`CSV error: CSV error: ...`); the HTTP server answers `HEAD` on a `get` route with 404; `--allow-read`/`--allow-write` and `allowedReadPaths` compare path strings without normalizing them (`data/../x` passes a rule for `data/`).

- [ ] **More static checking.** Status: `pleno check` reports syntax errors, compile errors and undefined names, and the language server syntax errors. Both also report, conservatively (done): wrong argument counts and unknown named arguments for top-level functions, constructors and `this` methods declared in the same file; unknown methods on `this` (a warning, for classes whose members are all known); and literals that cannot match a primitive annotation in `let` and in calls to those functions. Missing: compile errors and undefined names in the language server, calls on other receivers (`obj.method()` with a known class, static methods), calls to functions from imported modules, lambdas bound with `let`, mismatches beyond literals (inferring variable and return types), annotations that name classes, aliases or generic types, and parameter defaults and fields.
- [ ] **Error messages with suggestions.** Status: errors give the right line, operand types and actual types. Missing: "did you mean" suggestions for misspelled names and methods.
- [ ] **TCP sockets (`std:net`).** Status: `listen` binds and `connect` connects, but both close the socket at once and return a plain map. Missing: a socket resource with `accept`, `read`, `write` and `close`.
- [ ] **Web framework features.** Status: `std:http` has a router with `:param` routes, query strings, headers, bodies, `res.status/header/send/json` and async handlers. Missing: middleware (`app.use`), static files and cookies.
- [ ] **`with` statement** for resources that close themselves (`with (f = File.open(...)) { ... }`). Status: not started; the docs mark it as planned.
- [ ] **Package registry decision.** Status: `crates/pleno-registry` is a registry server (Axum + SQLite) and `plm` can publish to a registry URL from `PLENO_REGISTRY`, but none is deployed. Missing: either a hosted registry or Git-based dependencies as the 1.0 answer, and a documented protocol.
- [ ] **Language server tests and features.** Status: definition, references, rename, hover, completion, signature help, inlay hints, semantic tokens, folding, formatting, code lens, call hierarchy and code actions work. Missing: integration tests for the server and workspace symbol search.
- [x] **Formatter details.** Status: done. Lines are kept within 100 characters (the linter's limit): a statement that does not fit is broken at its outermost call, literal, parameter list, import list, method chain or operator chain, one element per line, and one that fits is joined. Comments in broken lists, chains, `match` arms and `enum` bodies stay in place. A round-trip test formats every test, example and docs code block and checks that the program is unchanged, a second pass changes nothing and no line is too long unless a string or comment makes it so; the tests and examples pass the same after formatting. Comments in places that cannot break (inside an index or an import list) still move below the statement.
- [ ] **Split the VM's `lib.rs`.** Status: `crates/pleno-vm/src/lib.rs` is about 6,200 lines (dispatch, calls, classes, exceptions, generics checks, iteration). Missing: modules small enough to review.
- [ ] **Code Runner support.** Status: the VS Code extension has its own Run command. Missing: Code Runner's executor map is a user setting the extension cannot safely change; document the setting instead.
